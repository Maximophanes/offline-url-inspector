## 5. Implemented boundary behavior

The boundary module implements longest exact/wildcard match, exception precedence, default `*`, registrable-domain extraction, PRIVATE/ICANN provenance, root dots, IDN/A-label correspondence and private tenant boundaries. Both sections are enabled for reference generation. ICANN-only lookup is explicit and independently tested.

`example.co.uk`, `tenant.github.io`, `tenant.blogspot.com`, `tenant.pages.dev`, `*.ck` and `!www.ck` follow the pinned rules. Independent private tenants remain independent; subdomains of one tenant can merge. Unknown TLDs retain the algorithm's default result with an ineligible status. Suffix-only, single-label, IP and invalid inputs are distinguished. Whitespace, credentials, paths, percent escapes, malformed labels and DNS length violations are rejected. The existing Inspector/native URL path remains the normalization authority, with Unicode 18.0.0 unchanged.

PSL classification says nothing about existence, ownership or safety.

## 6. Versioned contract

Schema 1 stores compact runtime tuples:

```text
[asciiDomain, globalRank, sourceRowCount, publicSuffixASCII, section]
```

`section` is `I`/`P`; the ASCII-sorted array index is a deterministic ID. Minimum contributing original GlobalRank determines rank and tier membership. Rich development provenance retains original hostnames, ranks, source-row ordinals, readable domain, normalized full hostname, prevailing rule/section and change evidence. It also retains every exclusion and its reason.

The manifest binds provider/source/subset/PSL/Unicode identities, licenses, selection and normalization policies, normalization runtime, generator/module hashes, counts and derived sizes/hashes. It explicitly declares `foundation-only`, `automaticMatchingAvailable: false`, `indexFormatVersion: null`. IDs are snapshot-relative, not cross-snapshot permanent identifiers. Unsupported schema, corruption, incompatible normalization/Unicode/PSL and unavailable crypto have explicit unavailable states.

## 14. Remaining risks and decisions

- Native Firefox/Safari behavior, file-context WebCrypto availability and browser memory are unverified. The dormant loader explicitly reports unavailable integrity support; the current inspector does not depend on it.
- Dataset rank is a biased popularity signal, not ownership or trust. Tiers need Stage 3 false-positive/calibration work before producing findings.
- Unknown suffixes and platform apexes are deliberately ineligible; caller code must check status rather than merely a non-null default-rule registrable result.
- Hashes bind reviewed trusted metadata and bytes; they do not independently authenticate a publisher or secure a replaced whole application.
- The exact normalization runtime is pinned. Future data/runtime changes require explicit review. Existing documented Deno/native-browser IDNA differences remain outside any claim of universal parser equivalence.
- Final MPL/source-availability packaging and release-verifier policy remain release-hardening decisions. The preview is not release-ready.
